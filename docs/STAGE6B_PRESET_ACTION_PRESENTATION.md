# Stage 6B — Stable preset action presentation

Status: implemented, automatically validated and **physically accepted on iPhone**.
The user approved closure before Stage 6B.5A on `codex/stage6b-web-ui`.

## Accepted baseline

The two-bundle migration was committed separately as:

`4e6fbbeada642e5dc8345421a1d11eb9acc6baa5`

`refactor(web): split embedded JavaScript into core and UI bundles`

Before that commit, deterministic generation, frontend/integration/host tests
and all four PlatformIO builds passed. The migration report records the user's

The user subsequently confirmed physical iPhone acceptance of this correction.

## Confirmed cause

`actions.available()` represents command admission. It becomes false while a
local preset or blackout operation awaits its matching result. The preset view
used that transient flag for all three buttons' native `disabled` properties.
That activated the existing global, primary-button and danger-button disabled
colors, then reversed them after acknowledgment. Only the initiating browser
has that local pending operation; remote clients receive authoritative state
without entering this pending state. The P1–P8 rendering loop was not the cause.

The browser regression failed against the accepted baseline: Load/Save/Delete
became disabled and changed background/text/border presentation even though the
selected slot, Sender readiness and authoritative blackout state remained valid.
The same test passes after the correction.

## Minimal correction

Only the action-presentation block in `web/src/js/presets.js` changes:

- Native disabled state derives from synchronized Sender readiness, actual slot
  validity and confirmation-dialog state.
- Temporary admission blocking is exposed as `aria-disabled="true"`. Native
  enabled appearance and keyboard focus remain stable during pending operations
  and the existing shared rate-budget wait.
- Mouse, Enter and Space still call the existing guarded handlers. Those handlers
  check `actions.available()` before doing anything, so blocked input cannot
  submit, queue, replay or open an overwrite/delete confirmation.
- Real disconnection, receiver mode, empty/corrupt/error slots and confirmations
  retain their intentional native disabled styling and keyboard exclusion.

Transient aria-disabled controls remain focusable, allowing users to retain
their position; they are announced as unavailable and cannot perform an action.
Existing polite pending/error feedback is preserved. No CSS override hides
disabled styling. No tiles, action handlers, command policies, header rendering,
Controller, Dispatcher, transport, NVS, HTTP or Wi-Fi behavior is changed.
The scope gate accepts exactly the reviewed render block; all thirteen other
application factories and the rest of the preset factory remain exact.

## Physical acceptance

On iPhone Safari and Home Screen mode:

1. Select an occupied preset and load by Load or double-tap. Repeat loading it,
   then alternate occupied presets. The three action buttons must not flash.
2. With Presets visible, toggle header blackout ON/OFF. Action-button appearance
   must remain stable; real blackout state and its lower Editor indicator update.
3. Repeat from the physical Controller and another browser. Verify Loaded/Modified
   metadata and all channel values synchronize normally.
4. Try rapid Load/Save/Delete or keyboard Enter/Space while a command is pending.
   There must be no duplicate operation or accidental confirmation dialog.
5. Verify Save/overwrite/Delete confirmations, empty/error slot restrictions and
   disconnect/reconnect. Genuine unavailable states must still look disabled;
   failures must remain visible and uncertain mutations must not replay.
6. Check keyboard focus/VoiceOver announcements where available, existing tiles,
   faders, compact channel status, DMX output and blackout restoration.

The fixture suite can be rerun with an installed Playwright/Chromium:

```text
node tests/web/test_preset_actions_browser.cjs --focused
node tests/web/test_preset_actions_browser.cjs
node tests/web/run_tests.mjs
python -B tests/web/check_pipeline.py
pio run -e cores3se_unit
pio run -e cores3se_base
pio run -e cores3se_unit_diagnostics
pio run -e cores3se_base_diagnostics
git diff --check
```

`DMX_PLAYWRIGHT_MODULE` and `DMX_CHROME_PATH` select the local test tools. Browser
fixtures never access the device or its stored presets. No automatic upload,
NVS operation, push, merge or Phase B commit was performed.
