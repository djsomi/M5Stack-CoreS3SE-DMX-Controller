# Web UI foundation and live read-only checks

Run from the repository root with the existing pinned PlatformIO Python
3.11.7 / zlib 1.2.13 environment:

```powershell
python -B scripts/web_asset_pipeline.py --generate
python -B tests/web/check_pipeline.py
node tests/web/run_tests.mjs
python -B tests/network/check_integration.py
python -B tests/network/check_websocket_integration.py
python -B tests/infrastructure/test_infrastructure.py
```

`--generate` is an explicit developer operation. Normal builds only verify
checked-in output. No Node/npm dependency is needed for generation or firmware
builds. The optional JS tests require Node with built-in ESM, assert and vm.
The Python tests use disposable fixture directories under ignored `dist/`.

`check_scope.py` protects exact Stage 6A firmware/build inputs. The only permitted
production exceptions outside `web/` are the named bundle composer/asset
pipeline and three explicitly named network diagnostic/I/O surfaces.
network_service.cpp also contains bounded SoftAP station tracing in the existing
DMX_HW_DIAGNOSTICS builds only; normal builds contain none of its state,
formatting, logging or MAC-tag work. The event-set/1 Hz native reconciliation
behavior is unchanged.
The I/O exception includes the tested sub-ms zero-timeout guard; it does not
authorize queue, driver or server-cadence changes.
Controller, Dispatcher, bridge, driver, scheduling, USB, Wi-Fi and layout remain
frozen; other firmware behavioral changes are prohibited. `check_pipeline.py` checks actual generated bytes, hashes, gzip limits,
Windows newline normalization, stale outputs, module ordering/dependencies,
corrupt/missing assets and non-live semantic markup. `run_tests.mjs` loads actual
factories in isolated contexts and checks preferences, all 512 bank positions,
factory scoping and generated bundle syntax. It also runs `test_live.mjs` against
mock WebSockets, timers and DOM nodes: protocol validation, atomic state,
ordering, bounded resync/results/reconnect, generations, rendering and resume.
The stability suite also covers 30 consecutive recoverable failures, precise
protocol classifications, repeated-integrity/version guards, full sweeps and
already-CLOSED errors followed by late native close events.
The idle-health cases cover an apparently OPEN black hole, matching snapshot
completion, a quiet Controller, delayed replies/timers and lifecycle cancellation.
Only existing read-only state.request probes are sent after 15 s of inactivity;
there is no HTTP polling. These tests do not establish electrical correctness
or replace device testing.

To inspect the three actual gzip assets locally with the existing device CSP:

```powershell
python -B tests/web/preview.py --port 8765
```

Open `http://127.0.0.1:8765/`; stop with Ctrl+C. The helper binds loopback only,
implements no device API and serves no arbitrary repository files. Restart it
after regenerating assets because content-hashed routes are loaded at startup.
A browser may optionally request an unserved favicon; this is not a dependency.
This static-only helper has no WS endpoint: Stage 6B.2 will correctly remain
unavailable/reconnecting, with expected native connection-failure messages.

For actual browser WS projection with synthetic test data only:

```powershell
python -B tests/web/fixture_server.py --port 8766
```

Open `http://127.0.0.1:8766/`. This loopback-only standard-library helper serves
the real assets/CSP and finite v1 fixture streams; it is not production firmware
or a Controller simulator. It rejects mutation requests. Stop/restart it to
check stale-state presentation and fresh-snapshot recovery. It provides no
evidence for actual ESP32 memory, DMX safety or multi-client hardware behavior.
Use --quiet to test a quiet but responsive peer. Use --stall-after 2 to keep TCP
open while dropping updates and snapshot replies: the UI should probe, time out,
retire the generation and recover with a fresh snapshot on a new connection.
These switches affect only the local fixture, never production firmware.

Browser checks: 320/390 px four columns, 600 px six, 768/1440 px eight; 1024 px
maximum app width; no horizontal overflow; four section links; local P8
selection; channel 512 bounds; invalid 513 rejected; percentage preference and
channel persistence after reload; all device actions/faders disabled; one page-
origin `/ws`, no HTTP polling/external requests/mutations, no JS/CSP errors when
the fixture is running. Only read-only `state.request` may be sent for resync.
Verify LIVE requires hello/full snapshot, stale values are labelled on loss,
Blackout is unknown while unsynchronized and all four preset codes are distinct.
Repeat with current Safari,
physical touch input, safe areas and 200% browser zoom before acceptance.

See `docs/STAGE6B1_WEB_UI_FOUNDATION.md` for all four build results, firmware
resource comparison, exact manual upload commands and physical regression
checklist and the user-confirmed Stage 6B.1 hardware acceptance. Stage 6B.2 is
documented in `docs/STAGE6B2_LIVE_WEBSOCKET_STATE.md`; its real-device acceptance
is still pending. Editing remains disabled until later approved phases.

On svh-capable browsers below 680 px, the body is a stable small-viewport frame
and `.app-container` is the one content scroller. Navigation is positioned to
the body outside that scroller's containing block. Check the root stays at
scroll offset zero; different tabs reset content to its top and active-tab taps
preserve their current offset;
the footer must remain clear above the bar at the end of content. Wider layouts
and browsers without svh retain document scrolling. The shipped CSS contract,
safe-area clearance and zoom metadata are checked by `check_pipeline.py`.
Browser geometry checks cannot emulate real Safari toolbar animations: use the
portrait/landscape, toolbar, private-tab and keyboard matrix in the report.


For station-count investigation host coverage, extract the actual callback,
query and logger (native SDK APIs are mocked in the C++ test):

```powershell
python -B tests/network/check_softap_integration.py --station-header dist/station_under_test.h
```

Compile tests/network/test_station_diagnostics.cpp with src/softap_policy.cpp
and the generated header directory on the include path, using the same C++11
host toolchain as the existing network cases. Compile once without diagnostic
defines for the production path, and with -DDMX_HW_DIAGNOSTICS=1 for detailed
station diagnostics. Cases cover cold boot, duplicate
and delayed events, native zero/one reconciliation, a callback during a query,
AP restart, failed queries, redaction and bounded logging. See the Stage 6B.2
report for physical USB capture instructions with cores3se_unit_diagnostics;
normal production builds are silent. No HTTP client is needed.


Final presentation regressions keep the main Connected / Live indicator stable
through routine health probes. Status may show the pending check; timeout still
changes the main shell to reconnecting/offline and marks cached values stale.
The endpoint mock cases also retain receive EOF (io_op4/errno0), reset and timeout
errors separately from an explicit complete WebSocket CLOSE. No error bucket is
cleared or relabelled to make counters appear clean.


## Stage 6B.3 active channel control

Stage 6B.2 has closed at `3eb72f31c61c53ae1617a3c7385d1327c884b5c8`.
Stage 6B.3 enables only native Editor channel faders after a synchronized Sender
snapshot. Preset/blackout controls stay disabled. Earlier read-only QA notes
above describe the historical Stage 6B.2 interface.

Run `node tests/web/run_tests.mjs` and `python -B tests/web/check_pipeline.py`.
The added groups execute the real command encoder, transport, pacing layer,
fader and Editor factories with deterministic sockets/clocks and DOM doubles.
They cover native input/change/pointerup contracts for mouse/touch/keyboard,
strict bounds/shared IDs, authoritative ack vs transport send, coalescing and
rolling rate bounds, final delivery, conflicting updates, eight-channel intent
capacity, bank identity including CH512, explicit rejections/transport errors,
resync, background and loss mid-drag, no mutation replay, and concurrent health
probes. These event mocks do not emulate Safari's actual range tracking or DMX.

The existing `fixture_server.py` remains a read-only projection fixture and
intentionally rejects channel mutations. Do not use it as evidence of active
control, controller authority, or multi-client conflict resolution. The C++
`test_websocket.cpp` executes the actual v1 decoder/Bridge/Dispatcher/Controller
with fake persistence; the Stage 6B.3 function adds untrusted-write rejection,
boundaries, applied/no_change acknowledgment ordering, independent/same-channel
clients and read-only observer compatibility. The existing blackout, preset,
transport and ISR tests remain required.

Use the physical acceptance matrix in `docs/STAGE6B3_ACTIVE_WEB_CONTROL.md` for
actual iPhone Safari/Home Screen, Windows, MacBook, physical controls and known
fixture channels. No automatic DMX sweep is part of any browser test.


Final Editor refinement tests also execute the +/- pending-intent arithmetic and
compact numeric editor. The banner is absent. Native number-button activation
opens a3-digit inputmode=numeric draft (18px mobile font); only Apply/Enter sends,
Cancel/Escape does not. Tests cover rapid tap accumulation, bounds, explicit final
pacing, immutable drafts under publications, rejection, stale disabling, no replay,
disposed handlers/bank identity and CH512 at4/6/8 columns. Pipeline assertions
check served selectors/ARIA,44px targets, equal form/rail height and zoom/selection
exceptions. Native iPhone keyboard/focus/zoom and actual touch geometry require
physical acceptance; the DOM doubles do not establish these browser behaviors.
