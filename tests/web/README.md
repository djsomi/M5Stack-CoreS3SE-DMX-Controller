# Web UI foundation checks

Run from the repository root with the existing pinned PlatformIO Python
3.11.7 / zlib 1.2.13 environment:

```powershell
python -B scripts/web_asset_pipeline.py --generate
python -B tests/web/check_pipeline.py
node tests/web/run_tests.mjs
python -B tests/network/check_integration.py
python -B tests/network/check_websocket_integration.py
python -B tests/infrastructure/test_infrastructure.py
```

`--generate` is an explicit developer operation. Normal builds only verify
checked-in output. No Node/npm dependency is needed for generation or firmware
builds. The optional JS tests require Node with built-in ESM, assert and vm.
The Python tests use disposable fixture directories under ignored `dist/`.

`check_scope.py` protects exact Stage 6A firmware/build inputs. The only permitted
production changes outside `web/` are the named bundle composer and asset
pipeline. `check_pipeline.py` checks actual generated bytes, hashes, gzip limits,
Windows newline normalization, stale outputs, module ordering/dependencies,
corrupt/missing assets and non-live semantic markup. `run_tests.mjs` loads actual
factories in isolated contexts and checks preferences, all 512 bank positions,
factory scoping and generated bundle syntax. These tests do not simulate a DMX
device, establish electrical correctness or replace browser DOM testing.

To inspect the three actual gzip assets locally with the existing device CSP:

```powershell
python -B tests/web/preview.py --port 8765
```

Open `http://127.0.0.1:8765/`; stop with Ctrl+C. The helper binds loopback only,
implements no device API and serves no arbitrary repository files. Restart it
after regenerating assets because content-hashed routes are loaded at startup.
A browser may optionally request an unserved favicon; this is not a dependency.

Browser checks: 320/390 px four columns, 600 px six, 768/1440 px eight; 1024 px
maximum app width; no horizontal overflow; four section links; local P8
selection; channel 512 bounds; invalid 513 rejected; percentage preference and
channel persistence after reload; all device actions/faders disabled; no page
WebSocket/fetch/DMX activity; no JS/CSP errors. Repeat with current Safari,
physical touch input, safe areas and 200% browser zoom before acceptance.

See `docs/STAGE6B1_WEB_UI_FOUNDATION.md` for all four build results, firmware
resource comparison, exact manual upload commands and physical regression
checklist and the user-confirmed hardware acceptance. The Stage 6B.1 UI remains
non-live; Stage 6B.2 will add read-only live synchronization in a separate change.

On svh-capable browsers below 680 px, the body is a stable small-viewport frame
and `.app-container` is the one content scroller. Navigation is positioned to
the body outside that scroller's containing block. Check the root stays at
scroll offset zero while long/short view changes clamp only container scroll;
the footer must remain clear above the bar at the end of content. Wider layouts
and browsers without svh retain document scrolling. The shipped CSS contract,
safe-area clearance and zoom metadata are checked by `check_pipeline.py`.
Browser geometry checks cannot emulate real Safari toolbar animations: use the
portrait/landscape, toolbar, private-tab and keyboard matrix in the report.
